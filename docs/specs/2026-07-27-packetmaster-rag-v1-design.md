## 1. 背景

PacketMaster 当前已经完成本地大报文流式分析、FastMCP 有界取证、LangGraph 单 Agent 诊断、CLI 持续对话和 Web 工作台。模型只接收经过白名单过滤的聚合摘要与分页证据，不接收原始报文、Payload、密钥或本地绝对路径。

现有模型能够根据当前报文提出开放式候选原因，但它不了解企业内部历史故障、设备特性、已验证处置经验，也不能稳定引用 TCP 标准和厂商资料。RAG V1 的作用是补充这些可追溯知识，提高原因覆盖率、解释准确性和排查建议质量，而不是替代当前报文证据。

## 2. 目标

RAG V1 需要实现：

1. 管理经过审核的 TCP 协议知识、厂商资料、内部手册和历史故障案例；
2. 使用诊断结构化特征、候选原因和用户问题进行混合检索；
3. 将知识片段以有界、可引用的形式提供给诊断图和分析后问答；
4. 明确区分报文直接证据、知识库经验和报文外假设；
5. 知识服务不可用时自动退化为当前无 RAG 流程；
6. 通过固定评估集证明 RAG 相比当前基线有可重复的质量提升；
7. 兼容 macOS 开发环境和 Windows 正式运行环境。

## 3. 非目标

RAG V1 不包含：

- 将 pcap/pcapng、Payload、完整逐包记录或完整运行日志写入知识库；
- 自动把模型回答或未确认报告加入正式知识库；
- 自动抓取互联网资料并直接用于生产诊断；
- 允许知识正文改变系统 Prompt、工具权限或执行本机命令；
- 建设多租户、分布式知识平台和复杂权限系统；
- 引入多 Agent 编排；
- 依赖 RAG 才能完成基础报文诊断。

## 4. 核心原则

### 4.1 证据优先级

诊断信息按以下顺序使用：

1. 当前报文直接证据；
2. 当前报文全量聚合指标；
3. 与当前环境和特征匹配的已审核历史案例；
4. TCP 标准、厂商资料和内部手册；
5. 当前报文不可观测的外部因素假设。

知识命中不能覆盖相反的报文证据。发生冲突时，报告保留冲突说明，并以当前报文为准。

### 4.2 确定性边界

文档解析、脱敏、切分、过滤、分数融合、引用校验、版本控制和上下文裁剪由确定性代码完成。模型只参与知识与当前现象的语义关联、原因补充和自然语言解释。

### 4.3 先评估再影响结论

RAG 首先以影子模式运行：记录召回结果并展示引用，但不改变主因。达到评估门槛后，才允许知识参与候选原因补充和排查建议生成。

## 5. 总体架构

```text
知识文件/历史案例
       |
       v
导入 -> 解析 -> 脱敏 -> 类型化切分 -> 人工审核 -> 建立索引
                                                    |
                                                    v
                                        Knowledge Store
                                      SQLite + FTS5 + Vector
                                                    ^
                                                    |
诊断上下文 -> Query Builder -> 混合检索 -> 重排 -> 引用打包
                                                    |
                       +----------------------------+------------------+
                       |                                               |
                       v                                               v
                LangGraph 诊断                                  分析后持续问答
                       |                                               |
                       +----------------------+------------------------+
                                              v
                                  报告/回答 + 报文引用 + 知识引用
```

知识库存储域与 Web 任务数据库、分析产物目录分离。删除诊断任务不得删除共享知识，停用知识也不得修改已完成报告保存的历史引用快照。

## 6. 技术选择

### 6.1 首版存储

RAG V1 使用独立 SQLite 数据库：

- 普通表保存文档、版本、切片、审核状态、向量元数据和审计记录；
- SQLite FTS5 提供关键词/BM25 检索；
- Embedding 以定长 `float32` 向量保存；
- 每个进程按索引代次加载只读向量矩阵，在内存中执行归一化点积检索；
- 写入、审核和重建索引使用事务，并通过索引代次使读缓存失效。

该方案避免 Qdrant Local 的目录进程锁问题，适合当前 Web API 与 Worker 分进程、Windows 单机运行的架构。V1 限制正式可检索切片不超过 25,000 条；超过该规模或出现多主机部署需求时，通过 `KnowledgeStore` 接口迁移到 Qdrant Server，不改变 Agent 契约。

### 6.2 Embedding

默认采用本地多语言 Embedding，建议模型为 `intfloat/multilingual-e5-small`：

- 支持中文内部案例与英文 RFC/厂商文档混合检索；
- 生成 384 维向量并进行归一化；
- 查询使用 `query:` 前缀，知识切片使用 `passage:` 前缀；
- 模型名称、维度、内容哈希和生成时间随向量保存；
- Embedding 作为 `rag` 可选依赖安装，避免增加基础 PacketMaster 安装体积；
- 首次下载后可离线使用，正式 Windows 环境允许配置预下载模型目录。

Embedding Provider 使用接口隔离。后续可接入企业内部或 OpenAI 兼容 Embedding 服务，但不得复用当前 DeepSeek 对话模型配置并假定其支持 Embedding。

### 6.3 为什么不直接使用纯向量检索

TCP 诊断包含 `zero_window`、`duplicate_ack`、拥塞算法名、设备型号和 RFC 编号等精确术语，纯向量检索容易漏掉这些关键词。V1 固定使用关键词、向量和结构化过滤三路信息，不能只依赖一种召回方式。

## 7. 知识模型

### 7.1 知识类型

| 类型 | 示例 | 默认权威等级 |
| --- | --- | --- |
| `standard` | RFC、标准组织文档、协议机制 | 高 |
| `vendor` | 操作系统、网卡、测速工具和设备文档 | 中高 |
| `runbook` | 已审核内部排查流程和处置手册 | 中高 |
| `case` | 人工确认原因和处置结果的历史案例 | 由审核结果确定 |

知识状态为 `draft`、`approved`、`disabled` 或 `superseded`。生产检索默认只能召回 `approved` 且当前有效的版本。

### 7.2 文档与版本

每份知识至少保存：

- `knowledge_id`：跨版本稳定标识；
- `version_id` 和版本号；
- 标题、知识类型、语言和摘要；
- 来源名称、来源位置、发布日期和导入时间；
- 权威等级、适用条件和环境标签；
- 内容哈希、审核状态、审核人和审核时间；
- 生效时间、失效时间和替代版本；
- 脱敏后的原文或结构化正文。

更新知识时创建新版本，不覆盖旧版本。完成的诊断报告保留当时使用的 `knowledge_id`、`version_id`、标题、来源位置和引用摘要。

### 7.3 历史案例

历史案例不能只保存最终结论，至少包含：

- 方向、标准带宽、实际带宽和达标率；
- 操作系统、链路类型、测速工具、设备和拓扑标签；
- 脱敏后的全局 TCP 指标；
- 异常流和异常时间区间摘要；
- 已确认主因、候选原因和不可观测因素；
- 支持证据、反向证据和证据覆盖范围；
- 实际处置动作、验证方法和最终结果；
- 确认人、审核人和置信等级；
- 原分析的非路径引用，不包含原始报文。

模型生成的自由文本只能作为案例描述，不能取代这些结构化字段。

### 7.4 切片

- 标准和厂商文档按章节、标题与语义段落切分；
- 内部手册按现象、前置条件、检查方法、判断标准、处置动作和风险切分；
- 案例保留一个结构化案例概要，并为现象、证据、原因和处置结果生成子切片；
- 表格、命令和阈值不能脱离标题、适用条件与风险说明；
- 每个切片建议 300 至 800 个中文字等效长度，最大 1,500 字；
- 相邻普通段落可保留不超过 100 字重叠，结构化案例不使用机械重叠；
- 每个切片必须能够追溯父文档、版本和章节位置。

## 8. 入库与审核

### 8.1 输入格式

V1 支持 Markdown、纯文本、JSON 结构化案例。PDF、Word 和 HTML 在 V1 中先由外部受控流程转换为 Markdown，避免首版同时承担复杂版面解析和 OCR 风险。

### 8.2 生命周期

```text
导入
  -> 文件类型/大小/编码校验
  -> 内容哈希去重
  -> 解析和结构校验
  -> 敏感信息扫描与脱敏
  -> Prompt 注入风险标记
  -> 类型化切分
  -> 草稿预览
  -> 人工审核
  -> 生成 Embedding 和 FTS 索引
  -> 发布为可检索版本
```

审核拒绝、停用和替代均保留审计记录。未经审核的内容不会进入生产索引。Embedding 失败时该版本不能发布，不能静默退化成只有关键词索引的不完整状态。

### 8.3 管理入口

RAG V1 先提供 CLI 管理入口，以降低 Web 管理界面的首版范围：

```text
pkm knowledge import
pkm knowledge list
pkm knowledge show
pkm knowledge approve
pkm knowledge disable
pkm knowledge reindex
pkm knowledge evaluate
```

Web 首版只展示诊断命中的知识引用。知识导入、审核和版本管理页面放在后续增量中。

## 9. 检索设计

### 9.1 查询输入

`KnowledgeQueryBuilder` 使用确定性代码从以下信息构建查询：

- `DiagnosisContext.target` 和带宽达标率区间；
- 全局 TCP 指标与 SYN 选项；
- 排名靠前的异常流和异常时间区间；
- 当前候选原因、反向证据和缺失证据；
- 用户明确提供的系统、设备、工具和拓扑标签；
- 分析后问答中的当前问题和当前报告摘要。

查询中禁止出现原始报文、Payload、完整逐包数据、本地绝对路径、API Key、Token 和未经白名单过滤的日志。

### 9.2 混合检索

```text
结构化查询
  -> 审核状态、知识类型、方向和环境元数据过滤
  -> FTS5/BM25 候选 Top 20
  -> 向量语义候选 Top 20
  -> Reciprocal Rank Fusion 合并
  -> 适用条件、权威等级、时效性和案例相似度重排
  -> 父文档去重与知识类型多样性控制
  -> Top 8 有界引用包
```

默认融合参数使用 RRF `k=60`。结构化环境不匹配是硬过滤或强降权条件，权威等级只能在相关结果之间调整顺序，不能把不相关的高权威文档推到前列。

故障案例额外计算结构化相似度，包括方向、达标率区间、重传、重复 ACK、乱序、RTT、窗口、并发流数量、SYN 选项和环境标签。各指标在缺失时不计分，不把“未知”当作匹配。

### 9.3 上下文预算

单次最终提供给模型的知识最多 8 条，总正文不超过 24 KB。每个父文档默认最多 2 条，至少保留一个位置给不同知识类型；若没有达到最低相关性阈值，则返回空结果，不为凑数注入低质量知识。

## 10. 引用契约

每个进入模型的知识片段包含：

- `knowledge_id` 和 `version_id`；
- `chunk_id`；
- 标题、知识类型和权威等级；
- 来源名称和章节位置；
- 适用条件；
- 审核状态；
- 有界正文；
- 关键词排名、向量排名、融合分数和重排分数。

模型输出增加知识引用，至少包含 `knowledge_id`、`version_id`、`chunk_id` 和该知识支持的具体陈述。确定性验证器检查：

1. 引用 ID 是否在本次召回包中；
2. 版本是否有效且审核通过；
3. 引用正文是否支持对应陈述；
4. 适用条件是否与当前环境冲突；
5. 知识结论是否与报文直接证据冲突。

不存在或失效的引用不得进入最终报告。无法确认支持关系时，该陈述降级为“待外部验证”，不能作为已确认原因。

## 11. LangGraph 接入

### 11.1 主诊断图

当前主流程为：

```text
validate -> analyze -> reason -> inspect_evidence -> verify -> report
```

RAG 达到影子模式评估门槛后调整为：

```text
validate -> analyze -> reason
                         |
                         v
               retrieve_knowledge
                         |
                         v
               augment_hypotheses
                         |
                         v
                inspect_evidence -> verify -> report
```

`reason` 继续只根据当前报文生成基础候选原因，避免知识库预先锚定模型。`retrieve_knowledge` 使用基础候选和诊断上下文检索；`augment_hypotheses` 只能补充候选原因、适用条件和排查建议，不能把案例相似性改写成报文直接证据。

`verify` 同时验证报文引用与知识引用。RAG 超时、索引不可用或无高质量命中时跳过两个 RAG 节点，沿用现有流程，并在 trace 和报告限制中记录降级原因。

### 11.2 分析后问答图

问答流程在首次回答前增加知识检索：

```text
prepare_question -> retrieve_question_knowledge -> answer_question
                 -> inspect_question_evidence -> verify_answer -> finalize_answer
```

只有涉及协议机制、相似案例、设备知识和处置方法的问题才启用知识检索。询问当前报文具体帧、流、时间区间或指标时，仍优先调用 MCP 证据工具。

## 12. 配置与运行模式

新增配置建议：

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `RAG_ENABLED` | `false` | 未通过评估前默认关闭生产影响 |
| `RAG_MODE` | `shadow` | `off`、`shadow` 或 `active` |
| `KNOWLEDGE_DATABASE_PATH` | `artifacts/knowledge/packetmaster-knowledge.sqlite` | 独立知识数据库 |
| `EMBEDDING_PROVIDER` | `local` | 本地或后续远端 Provider |
| `EMBEDDING_MODEL` | `intfloat/multilingual-e5-small` | 多语言模型 |
| `EMBEDDING_MODEL_PATH` | 空 | Windows 离线模型目录 |
| `RAG_KEYWORD_TOP_K` | `20` | 关键词候选数 |
| `RAG_VECTOR_TOP_K` | `20` | 向量候选数 |
| `RAG_FINAL_TOP_K` | `8` | 最终知识数量 |
| `RAG_MAX_CONTEXT_BYTES` | `24576` | 模型知识正文上限 |
| `RAG_TIMEOUT_SECONDS` | `2` | 单次检索超时 |

`shadow` 模式执行检索并记录评估数据，但不允许改变主因；`active` 模式允许补充候选原因和建议。模式变化不需要迁移知识数据。

## 13. 安全与隐私

- 入库前执行来源校验、敏感字段扫描、脱敏和 Prompt 注入风险标记；
- 文档中的命令和指令始终作为引用数据，不授予工具权限；
- 正式知识只能由人工审核发布；
- 查询和检索结果在进入模型前再次通过字段白名单和大小限制；
- 日志只记录知识 ID、版本、分数、耗时和错误码，不记录完整知识正文；
- 不向浏览器返回知识数据库路径、原始导入路径和审核者凭据；
- 历史案例中的 IP、域名、账号、工单号和客户信息按配置进行脱敏或哈希化；
- API Key 和本地配置不得进入知识导入目录、Embedding 文本或诊断引用。

## 14. 可观测性与降级

每次检索 trace 记录：

- 查询类型和结构化标签数量；
- FTS、向量和最终结果数量；
- 命中的知识 ID、版本、排名和分数；
- 过滤、去重和裁剪数量；
- Embedding、检索和重排耗时；
- 当前 RAG 模式；
- 超时、索引版本不匹配和降级原因。

以下情况自动退化到无 RAG 流程：

- RAG 被关闭或知识库为空；
- 本地 Embedding 模型不可用；
- 数据库锁、索引损坏或版本不兼容；
- 检索超时；
- 没有达到相关性阈值的结果；
- 引用验证失败。

降级不得使基础诊断失败，也不得返回部分未经验证的知识结论。

## 15. 测试与评估

### 15.1 自动化测试

- 文档解析、案例 Schema、脱敏、切分、版本和状态迁移测试；
- FTS、向量、元数据过滤、RRF、结构化案例相似度和去重测试；
- 待审核、停用、过期和环境不匹配知识不可被错误召回；
- 缺失、伪造、跨版本和不支持陈述的引用被拒绝；
- Prompt 注入文档不能改变 Agent 权限或工作流；
- 空库、模型缺失、数据库损坏和超时均能回退到当前诊断图；
- Windows 路径、文件锁和离线模型目录测试；
- 同一知识和同一查询在 macOS 与 Windows 上产生一致的确定性融合顺序。

### 15.2 离线评估集

建立不少于 50 条脱敏查询/案例，覆盖：

- 拥塞、丢包和重传；
- RTT、带宽时延积与窗口限制；
- 接收端 Zero Window 和 Window Full；
- 乱序、重复 ACK 和链路聚合路径变化；
- MSS、窗口缩放、SACK 和 TCP 协商；
- 单流限制、并发流差异和测速工具行为；
- 客户端、服务端、网卡、虚拟化和中间设备因素；
- 报文内无法直接观测的外部因素；
- 无正确知识、冲突知识和环境不适用知识。

评估至少计算 Recall@5、MRR、nDCG@5、引用准确率、适用条件准确率、原因覆盖率、无依据陈述率、P95 延迟和 Token 增量。

### 15.3 上线门槛

从 `shadow` 切换到 `active` 必须同时满足：

- Recall@5 不低于 85%；
- 引用准确率不低于 95%；
- 适用条件准确率不低于 95%；
- 报文证据一致性不得低于无 RAG 基线；
- 原因覆盖率相对基线有正向提升；
- 无依据知识陈述率不得高于基线；
- 25,000 切片内检索 P95 不超过 2 秒；
- RAG 故障时现有 CLI、Web 和诊断流程回归通过。

## 16. 分阶段交付

### 阶段 R1：知识基础设施

- 定义领域契约和数据库迁移；
- 实现 Markdown、文本和 JSON 案例导入；
- 实现脱敏、类型化切分、审核、版本和停用；
- 实现本地 Embedding、FTS5 和向量索引；
- 提供 `pkm knowledge` 管理命令。

### 阶段 R2：检索与评估

- 实现结构化 Query Builder、混合检索、重排和引用包；
- 建立不少于 50 条固定评估集；
- 固化无 RAG 基线并运行影子模式；
- 调整阈值和权重，达到上线门槛。

### 阶段 R3：诊断与问答接入

- 在主诊断图接入检索、候选原因补充和引用验证；
- 在分析后问答接入按需知识检索；
- CLI、Web 报告和对话展示知识引用；
- 验证超时、空库、模型缺失和索引损坏时的降级路径。

### 阶段 R4：知识管理增量

- 根据实际使用反馈决定是否增加 Web 导入和审核页面；
- 建立历史诊断转待审核案例的辅助流程；
- 知识量或部署规模超过 V1 边界时评估 Qdrant Server。

## 17. 验收标准

RAG V1 完成时应满足：

1. 只有审核通过且有效的知识可以进入生产检索；
2. 原始报文、Payload、密钥和绝对路径不会进入知识库或 Embedding；
3. 每项知识性结论能追溯到具体知识、版本和切片；
4. 报文证据与知识冲突时以报文证据为准并展示冲突；
5. RAG 不可用时 PacketMaster 仍可完成当前诊断和问答；
6. CLI 和 Web 使用同一 Knowledge Service 和引用契约；
7. macOS 开发验证和 Windows 真机验证均通过；
8. 固定评估集达到第 15.3 节门槛后才启用 `active` 模式。

## 18. 待确认事项

在生成实施 plan 前需要确认：

1. 首批知识来源及格式：RFC、内部 Markdown 手册、历史报告或结构化故障案例；
2. 谁负责正式知识的人工审核与主因确认；
3. Windows 正式环境是否允许首次联网下载 Embedding 模型，还是必须提供离线模型包；
4. 首批知识预计文档数、切片数和主要语言；
5. 历史案例允许保留哪些脱敏后的环境标签。
