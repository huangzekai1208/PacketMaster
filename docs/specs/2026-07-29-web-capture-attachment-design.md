# Web 报文附件发送设计

日期：2026-07-29

## 目标

用户在文件选择器中选定并加载报文后，报文作为待发送附件显示在输入区；用户可补充描述或问题，再将文字和 `capture_id` 一并发送到对话区。

## 交互与状态

- 点击“加载报文”直接触发浏览器本地文件选择器；选择新报文后自动上传、注册并更新当前会话的待发送附件，不调用消息 API，也不显示二次确认弹窗。
- 输入区显示文件名、大小和移除按钮。切换会话或新建会话时清除待发送附件，避免跨会话误发。
- 点击发送时，普通会话调用消息 API，正文和 `capture_id` 在同一请求提交；乐观消息立即显示。
- 若用户未输入文字，前端使用明确的默认说明“请使用已附加的报文进行测速诊断”，使附件单独发送仍满足 API 的文本字段要求。
- 请求失败时，回滚乐观消息，并恢复用户文字和待发送附件。

## 验收

- 点击加载报文直接打开本地文件选择器；选择/上传报文后，对话区没有自动新增消息。
- 输入区立即显示附件，用户可移除、补充文字或直接发送。
- 发送后消息立即显示；后端收到同一条消息中的 `capture_id`。
