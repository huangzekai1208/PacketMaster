# Web 回复等待状态设计

日期：2026-07-29

## 目标

将“注册报文”统一更名为“加载报文”，并在用户消息已发送、模型回复尚未完成期间提供清晰的阶段性等待反馈。

## 方案

- 所有可见入口使用“加载报文”；底层上传/注册 API 名称保持兼容。
- 发送消息后立刻展示用户的乐观消息，并在其后展示一个临时助手状态行。
- 状态行按固定间隔轮换 `Thinking…`、`Cooking…`、`Reviewing context…`、`Preparing reply…`，请求完成或失败后自动消失。
- 状态行仅表示请求仍在处理，不呈现模型内部推理、工具调用细节或任何隐藏思维链。

## 验收

- 界面不再显示“注册报文”。
- 挂起的消息请求期间可见 `Thinking…` 等状态文案，收到回复后消失。
- 状态文案不会写入会话数据库或作为模型回复保存。
