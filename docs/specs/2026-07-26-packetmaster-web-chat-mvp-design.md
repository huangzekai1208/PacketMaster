# PacketMaster Web 对话界面 MVP 设计

日期：2026-07-26

状态：待评审

关联文档：

- `docs/packetmaster-current-capabilities-and-workflow.md`
- `docs/specs/2026-07-24-packetmaster-v2-rag-web-multi-agent-design.md`

## 1. 背景

PacketMaster 当前通过 `packetmaster diagnose` 和 `packetmaster chat` 提供 TCP 测速不达标诊断。CLI 已具备自然语言参数抽取、用户确认、全量报文分析、有界证据推理、报告输出和持续问答，但存在以下使用门槛：

- 用户无法直观看到当前任务、参数和分析阶段；
- 长时间分析期间缺少持续、结构化的状态反馈；
- 报告、流、时间区间和关键证据不便比较；
- CLI 退出后无法恢复会话；
- 多个历史任务不便管理和继续追问。

本阶段建设一个本地 Web 对话工作台，将现有诊断闭环可视化。MVP 不改变诊断算法，不引入 RAG 和多 Agent，也不建设公网 SaaS。

## 2. 产品目标

用户启动 PacketMaster Web 后，可以在浏览器完成：

1. 创建、查看和恢复诊断会话；
2. 通过自然语言描述诊断需求；
3. 注册本机 pcap/pcapng 文件；
4. 查看并修改系统识别出的带宽、方向和文件信息；
5. 确认后启动后台分析；
6. 实时查看阶段、进度、耗时和处理规模；
7. 查看中文诊断报告和关键指标图表；
8. 按流、时间区间和类型查看有界证据；
9. 围绕当前 `analysis_id` 持续追问；
10. 取消运行中的任务，或重试失败任务。

## 3. 非目标

MVP 不包含：

- RAG 故障案例和网络知识库；
- 多 Agent 分工协作；
- 多用户、组织、角色和权限管理；
- 公网部署；
- 浏览器内解析报文；
- 数 GB 报文普通 HTTP 上传；
- 分片上传和断点续传；
- 在 Web 中修改网络或操作系统配置；
- 完整逐包浏览器表格；
- 替换现有 CLI；
- 将模型未校验的 Token 实时输出到页面。

## 4. MVP 决策

### 4.1 部署模式

- PacketMaster Web 与报文文件位于同一台 Windows 或 macOS 主机；
- 后端默认只监听 `127.0.0.1`；
- 首版不提供身份认证，因此禁止监听非本机地址；
- 通过 `packetmaster web` 启动后端和静态前端，并自动打开浏览器；
- CLI 继续独立可用，不依赖 Web 服务。

### 4.2 技术栈

| 层 | 选择 |
| --- | --- |
| 前端 | React、TypeScript、Vite |
| 前端路由 | React Router |
| 请求与缓存 | TanStack Query |
| 图表 | Apache ECharts |
| 图标 | Lucide React |
| 后端 | FastAPI、Pydantic |
| 实时进度 | Server-Sent Events |
| 本地持久化 | SQLite，WAL 模式 |
| 后台执行 | 独立本地 Worker 进程 |
| 诊断核心 | 现有 LangGraph、FastMCP、RealAnalyzerAdapter 和 speed-analyze |

MVP 不引入 Redis、Celery、PostgreSQL、Next.js、Electron 和 Kubernetes。

### 4.3 报文输入

首版使用“本机路径注册”，不通过浏览器上传报文：

1. 用户在页面输入或粘贴本机文件路径；
2. 后端校验文件存在、后缀、大小、可读性和允许目录；
3. 后端保存真实路径，返回不透明 `capture_id`、文件名和文件大小；
4. 后续前端请求只使用 `capture_id`；
5. 真实绝对路径不得进入模型、SSE、普通日志和前端持久化状态。

页面可以提供最近使用文件和 `samples` 目录中的候选文件，但不得递归扫描整个磁盘。

浏览器文件选择和分片上传作为后续能力。若未来需要原生文件选择且不复制大文件，可以使用 Tauri 包装同一套 React 前端，不纳入本 MVP。

## 5. 用户工作流程

### 5.1 首次进入

```text
启动 packetmaster web
  |
  v
浏览器打开本地工作台
  |
  +-- 存在历史任务 -> 显示最近会话
  |
  +-- 无历史任务 -> 自动创建空白会话
```

首屏直接显示对话工作台，不展示营销首页或功能介绍页。

### 5.2 创建诊断

```text
自然语言输入或注册报文
  |
  v
对话意图路由与参数抽取
  |
  +-- 普通问题 -> 普通对话回答
  |
  +-- 缺少参数 -> 对话补问 + 右侧参数同步更新
  |
  +-- 参数完整 -> 显示确认区
                         |
                         +-- 修改 -> 回到参数收集
                         |
                         +-- 确认 -> 创建后台分析任务
```

未明确方向时固定使用下载。只有用户明确选择上行或双向时才改变方向。

### 5.3 分析过程

```text
任务排队
  |
  v
校验 -> 报文扫描 -> 流筛选 -> TCP 聚合 -> 原因生成
     -> 证据查询 -> 原因复核 -> 报告生成
  |
  v
完成 / 部分完成 / 失败 / 已取消
```

页面在任务运行期间继续可用。用户可以查看历史任务，但一个会话在当前分析结束前不能重复启动第二个分析。

### 5.4 诊断后问答

报告生成后，对话输入自动绑定当前 `analysis_id`：

- 报告问题进入有界证据问答图；
- 普通问题进入普通对话模型；
- 问答不重新执行基础报文分析；
- 额外证据仍遵守每题最多 2 轮、每轮最多 5 个请求；
- 切换历史任务时，对话和证据同时切换到对应 `analysis_id`。

## 6. 页面信息架构

### 6.1 桌面布局

```text
┌────────────────────────────────────────────────────────────────────┐
│ PacketMaster                     连接状态        设置       新建任务 │
├──────────────┬────────────────────────────────┬────────────────────┤
│ 会话与任务   │ 对话和诊断主区域               │ 当前任务上下文     │
│              │                                │                    │
│ 搜索         │ 消息历史                       │ 报文文件           │
│ 运行中       │ 参数补问                       │ 标准/实际带宽      │
│ 最近完成     │ 参数确认                       │ 分析方向           │
│ 失败         │ 分析进度                       │ 覆盖与状态         │
│              │ 报告摘要                       │ 关键指标           │
│              │                                │                    │
│              │ 对话输入                       │ 报告/流/证据入口   │
└──────────────┴────────────────────────────────┴────────────────────┘
```

建议尺寸：

- 左栏默认 260 px，可折叠；
- 右栏默认 320 px，可折叠；
- 中间区域最小宽度 560 px；
- 顶栏保持紧凑，不使用大标题和营销式 Hero；
- 页面主体占满视口，内部滚动区域彼此独立。

### 6.2 窄屏布局

- 中间对话区作为主视图；
- 会话列表和任务上下文进入左右抽屉；
- 报告图表改为单列；
- 固定底部输入区不能遮挡消息和确认按钮；
- MVP 重点保证常见笔记本和桌面视口，手机只保证基本可用。

### 6.3 页面和视图

MVP 使用一个工作台页面和任务详情子视图：

| 视图 | 内容 |
| --- | --- |
| 工作台 | 会话列表、对话、参数、当前状态 |
| 报告 | 主因、候选原因、证据、限制和建议 |
| 指标 | 吞吐、RTT、重传和窗口图表 |
| TCP 流 | 流列表、排序、筛选和流详情 |
| 证据 | 证据类型、流、时间范围和分页结果 |

这些视图使用页内标签切换，不为每项指标创建独立页面。

## 7. 对话界面设计

### 7.1 消息类型

对话流支持以下消息：

- 用户文本；
- Agent 普通回答；
- 参数补问；
- 参数确认；
- 系统状态；
- 分析进度；
- 诊断报告摘要；
- 证据约束回答；
- 错误和恢复建议。

系统状态和进度使用紧凑行，不伪装成 Agent 自然语言消息。

### 7.2 输入区

- 多行文本输入，默认高度 44 px，可增长但不超过 160 px；
- Enter 发送，Shift+Enter 换行；
- 文件按钮打开“注册本机报文”对话框；
- 发送按钮使用 Lucide 图标并提供 tooltip；
- 分析运行时仍允许普通提问，但禁止重复确认启动；
- 空内容不能发送；
- 输入长度沿用后端 2000 字符限制，并显示临界提示。

### 7.3 参数确认区

参数完整后在消息流中显示一个独立确认面板：

- 报文文件名和大小；
- 标准带宽及原始单位；
- 实际带宽及原始单位；
- 归一化后的 Mbps；
- 分析方向；
- 默认值或推断值说明；
- `修改` 和 `开始分析` 命令。

真实路径不显示在确认区。用户需要修改文件时重新打开报文注册对话框。

### 7.4 回答呈现

诊断后回答不能只展示 `answer` 文本，还需要按需展示：

- 报文证据引用；
- 知识引用，MVP 预留但当前为空；
- 限制条件；
- 后续建议；
- 额外取证状态。

证据引用可点击，点击后打开右侧证据详情并定位对应帧、流或时间区间。

模型回答必须通过结构化 Schema 校验后整体显示。SSE 只推送回答状态，不推送未校验的模型 Token。

## 8. 报告与可视化

### 8.1 报告摘要

报告首屏显示：

- 标准带宽、实际带宽和达标率；
- 分析方向；
- 主要原因和置信度；
- 报文覆盖是否完整和是否截断；
- 关键证据数量；
- 限制条件。

### 8.2 候选原因

候选原因使用可展开列表，每项包含：

- 原因；
- 置信度；
- 可观测性；
- 支持证据；
- 反向证据；
- 缺失证据；
- 受影响流；
- 排查建议。

不把候选原因强制限制为固定数量，不用仅靠颜色表达置信度。

### 8.3 图表

MVP 提供：

1. 吞吐量时间序列，并显示标准带宽参考线；
2. RTT 分布；
3. 重传、重复 ACK、乱序、零窗口和窗口满事件时间线；
4. 各 TCP 流吞吐量排名；
5. TCP 窗口随时间变化；
6. 标准、实际和报文测得吞吐的对比。

图表数据来自聚合摘要。前端不得请求完整逐包序列。正常区间允许降采样，但异常区间、覆盖范围和截断状态必须保留。

### 8.4 证据查看

- 默认按证据类型和时间排序；
- 支持按流、时间区间和事件类型过滤；
- 使用服务端分页，默认每页 50 条；
- 只显示 MCP 字段白名单允许的字段；
- 不显示 TCP Payload；
- 证据响应必须绑定当前 `analysis_id`。

## 9. 前端状态模型

前端区分服务端持久状态和临时界面状态。

服务端状态：

- 会话和消息；
- 报文引用；
- 待确认参数；
- 分析任务和状态；
- 进度事件；
- 报告和证据引用；
- 当前 `analysis_id`。

前端临时状态：

- 当前选中的会话和标签；
- 左右栏展开状态；
- 图表缩放范围；
- 未发送的输入草稿；
- 当前证据筛选条件。

服务端状态由 TanStack Query 管理，避免再建立一套重复的全局状态。输入草稿和布局状态可以保存在浏览器本地，但不得保存真实绝对路径、API Key、完整报告或证据数据。

## 10. 后端服务边界

### 10.1 应用服务

现有 `run_diagnosis` 需要从 CLI 模块提取到与界面无关的应用服务。CLI 和 Web 都调用该服务，服务负责：

- 创建和校验任务；
- 运行诊断图；
- 保存报告和 trace；
- 返回结构化结果；
- 传播进度、取消和错误；
- 不直接调用 Typer 或 FastAPI。

### 10.2 后台 Worker

报文分析不能运行在 FastAPI 请求协程中。MVP 使用一个独立 Worker 进程：

- 默认并发数为 1，可通过配置调整；
- Windows 使用 `spawn` 兼容的进程启动方式；
- Worker 从 SQLite 领取 `queued` 任务；
- 定期写入心跳和进度；
- API 进程重启后，未结束任务可以识别为中断并提供重试；
- 取消请求由任务表记录，Worker 安全终止 TShark 子进程树；
- 不使用 Shell 字符串启动子进程。

### 10.3 持久化

SQLite 至少包含：

- `sessions`：会话和当前任务；
- `messages`：有界对话消息和类型；
- `captures`：报文引用、文件名、大小、哈希和后端路径；
- `analyses`：参数、状态、阶段、错误和报告位置；
- `analysis_events`：有序进度事件；
- `chat_turns`：诊断后问题、回答和引用。

数据库不保存报文二进制、Payload、API Key 和完整模型消息。真实路径需要存储时仅存在后端数据库，并禁止通过普通 API 返回。

## 11. 任务状态机

```text
draft
  |
  v
awaiting_confirmation
  |
  v
queued -> validating -> analyzing -> reasoning -> verifying -> reporting
                                                             |
                                                             v
                                                          completed
```

终止和降级状态：

- `partial`：已有可用报告，但分析或模型步骤部分失败；
- `failed`：没有可用诊断报告；
- `cancelled`：用户取消且子进程已终止；
- `interrupted`：服务异常退出，任务状态需要人工重试。

状态只能按照允许路径迁移。重复确认、重复取消和重复事件必须保持幂等。

## 12. API 设计

### 12.1 会话

| 方法 | 路径 | 功能 |
| --- | --- | --- |
| `POST` | `/api/sessions` | 创建会话 |
| `GET` | `/api/sessions` | 分页查询会话 |
| `GET` | `/api/sessions/{session_id}` | 获取会话、消息和当前任务 |
| `DELETE` | `/api/sessions/{session_id}` | 删除会话引用，不立即删除共享产物 |
| `POST` | `/api/sessions/{session_id}/messages` | 提交普通对话或诊断输入 |

### 12.2 报文

| 方法 | 路径 | 功能 |
| --- | --- | --- |
| `POST` | `/api/captures/register` | 注册并校验本机报文路径 |
| `GET` | `/api/captures/recent` | 获取最近使用的脱敏文件列表 |
| `DELETE` | `/api/captures/{capture_id}` | 删除引用，不删除用户原文件 |

### 12.3 分析

| 方法 | 路径 | 功能 |
| --- | --- | --- |
| `POST` | `/api/analyses` | 根据已确认参数创建分析 |
| `GET` | `/api/analyses/{analysis_id}` | 获取任务状态和阶段 |
| `POST` | `/api/analyses/{analysis_id}/cancel` | 请求安全取消 |
| `POST` | `/api/analyses/{analysis_id}/retry` | 基于原参数创建新任务 |
| `GET` | `/api/analyses/{analysis_id}/events` | SSE 进度事件 |
| `GET` | `/api/analyses/{analysis_id}/report` | 获取结构化报告 |
| `GET` | `/api/analyses/{analysis_id}/metrics` | 获取有界图表数据 |
| `GET` | `/api/analyses/{analysis_id}/evidence` | 获取分页证据 |
| `POST` | `/api/analyses/{analysis_id}/chat` | 提交诊断后问题 |

所有响应使用统一成功或错误 Schema。错误包含稳定错误码、中文消息、是否可恢复和建议动作，不返回内部堆栈。

## 13. SSE 事件

事件使用单调递增 `event_id`，支持浏览器通过 `Last-Event-ID` 断线续传。

| 事件 | 说明 |
| --- | --- |
| `analysis_status` | 任务状态发生变化 |
| `analysis_progress` | 阶段、处理规模和耗时变化 |
| `analysis_completed` | 报告已生成 |
| `analysis_partial` | 降级报告已生成 |
| `analysis_failed` | 任务失败 |
| `analysis_cancelled` | 任务已安全取消 |
| `chat_status` | 问答正在生成或查询证据 |
| `chat_answer_ready` | 已通过 Schema 校验的回答可读取 |

SSE 不传输模型 Prompt、隐藏推理、完整报告、完整证据和本地绝对路径。

## 14. 视觉设计原则

- 定位为安静、紧凑、面向重复工作的网络诊断工具；
- 使用中性背景、清晰边界和少量状态色，不使用大面积单一蓝色或紫色渐变；
- 绿色表示完成，橙色表示部分完成或注意，红色表示失败，蓝色仅用于选择和链接；
- 卡片只用于独立重复项和确认面板，不嵌套卡片；
- 使用 Lucide 图标表示新建、发送、取消、刷新、展开和下载；
- 不使用装饰性插画、渐变球和营销式大标题；
- 所有图表、状态和错误不能只依赖颜色表达；
- 文件名、流 ID 和长原因文本必须支持换行或省略提示，不得溢出容器；
- 所有按钮具有稳定尺寸和加载/禁用状态，避免布局跳动。

## 15. 安全与隐私

### 15.1 网络边界

- 默认只绑定 `127.0.0.1`；
- Host 校验拒绝非本机访问；
- 不提供关闭安全检查后监听公网的快捷配置；
- 未来启用内网模式前必须单独设计认证、授权和 TLS。

### 15.2 文件边界

- 允许目录通过配置明确指定；
- 路径先规范化再检查是否位于允许目录；
- 拒绝符号链接逃逸、目录、设备文件和非 pcap/pcapng 文件；
- 注册接口限制请求频率和路径长度；
- 删除 capture 只删除 PacketMaster 引用，不删除用户原始报文。

### 15.3 模型边界

继续禁止以下内容进入模型：

- 原始报文和 Payload；
- 完整逐包数据；
- 完整日志；
- API Key、Authorization 和密码；
- 本地绝对路径。

前端不得读取或配置模型 API Key。密钥只由后端环境或本地配置加载。

## 16. 错误与恢复体验

前端根据稳定错误码提供明确动作：

| 错误 | 用户提示和动作 |
| --- | --- |
| 文件不存在 | 重新注册报文 |
| 路径不在允许目录 | 修改允许目录或选择其他文件 |
| TShark 不可用 | 展示安装和 `TSHARK_PATH` 配置说明 |
| 磁盘空间不足 | 展示所需和可用空间 |
| 模型连接失败 | 保留基础分析并允许重试推理 |
| 模型结构错误 | 显示结构化输出失败并允许重试 |
| 分析超时 | 保留产物并允许使用更长超时重试 |
| Worker 中断 | 标记 interrupted，允许创建重试任务 |
| SSE 断开 | 自动重连并从最后事件继续 |

错误不能只显示“失败”或 Python 异常文本。

## 17. 性能要求

- 首屏在本机开发环境冷启动后 3 秒内可交互；
- 创建会话和注册正常本地文件路径 P95 不超过 500 ms，不含文件哈希全量计算；
- 创建分析任务在 1 秒内返回，不等待诊断完成；
- 状态变化后 2 秒内通过 SSE 到达前端；
- 会话列表和消息使用分页，单次最多返回 50 个会话或 100 条消息；
- 图表单次数据不超过 5000 个点，异常区间优先保留；
- 证据默认每页 50 条，最大 500 条；
- 前端任何 API 响应不包含 pcap 二进制或完整逐包集合；
- Web 接入不得破坏现有数 GB 报文内存门禁。

## 18. 可访问性和键盘操作

- 所有命令可通过键盘完成；
- 焦点顺序与视觉顺序一致；
- 输入、对话框、标签和按钮具有可访问名称；
- 状态变化通过 `aria-live` 适度播报，不重复播报每个报文进度；
- 图表提供文本摘要和可访问数据表入口；
- 文本和背景满足 WCAG AA 对比度；
- 尊重系统减少动画设置。

## 20. 验收标准

MVP 完成必须满足：

1. `packetmaster web` 能启动本地服务并打开可用工作台；
2. 用户能够创建和恢复会话；
3. 普通对话与诊断任务能够正确路由；
4. 用户能够注册本机 pcap/pcapng，前端后续只使用 `capture_id`；
5. 参数可以一次提供或逐项补充，确认前不得启动分析；
6. 分析在独立 Worker 中运行，关闭或刷新页面不终止任务；
7. 页面能够通过 SSE 恢复和展示有序进度；
8. 用户能够取消任务，TShark 子进程树被可靠终止；
9. 报告、候选原因、覆盖率、流、图表和分页证据可查看；
10. 诊断后问答绑定当前 `analysis_id`，且不重新执行基础分析；
11. 浏览器、模型、SSE 和普通日志不包含原始报文、Payload、密钥和绝对路径；
12. CLI 行为和现有报告契约保持兼容；
13. Windows 和 macOS 自动化测试通过；
14. Playwright 截图验证常用视口没有文本溢出和控件重叠。

## 22. 评审结论项

生成实施 plan 前需要确认：

1. MVP 是否接受“输入或粘贴本机路径”，暂不提供浏览器文件上传；
2. 是否接受默认只监听 `127.0.0.1` 且不提供登录；
3. 是否接受首版后台任务默认并发数为 1；
4. 是否接受 SQLite 作为会话和任务持久化；
5. 是否接受 React、TypeScript、Vite、FastAPI、SSE 和 ECharts 技术组合；
6. 是否将 Tauri 原生文件选择明确放到 MVP 之后；
7. 是否需要在 MVP 首版展示完整 TCP 流列表，还是先只展示异常流和前 20 条流。

本 spec 确认后再生成中文实施 plan。在 spec 和 plan 均确认前不开始功能代码编写。
