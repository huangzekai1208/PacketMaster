# PacketMaster RAG V1 实施计划

日期：2026-07-27

状态：已确认，实施中

依据：`docs/specs/2026-07-27-packetmaster-rag-v1-design.md`

## 1. 已确认决策

- RAG 用于补充知识和历史经验，不替代当前报文直接证据。
- 首版采用 SQLite 元数据、FTS5 关键词索引和本地向量检索。
- 默认使用本地多语言 Embedding，建议模型为 `intfloat/multilingual-e5-small`。
- Embedding 依赖作为可选 RAG 依赖，不增加基础 PacketMaster 的强制安装体积。
- 正式可检索切片上限为 25,000 条，超过后评估 Qdrant Server。
- 先提供 `pkm knowledge` CLI 管理能力，Web 首版只展示知识引用。
- RAG 先以 `shadow` 模式运行，达到评估门槛后才能切换到 `active`。
- RAG 不可用、无命中或引用无效时退化到当前无 RAG 流程。
- Windows 是正式运行平台，macOS 是开发兼容平台。

## 2. 全局实施约束

- 后续功能编码以本 spec 和 plan 为边界；设计变更先更新文档。
- 默认诊断方向继续为 `download`，只有用户明确说明才使用 `upload` 或 `both`。
- 原始报文、Payload、完整逐包数据、API Key、Token、完整日志和本地绝对路径不得进入知识库、Embedding 或模型知识上下文。
- 只有 `approved` 且有效的知识版本可以进入生产检索。
- 知识性结论必须引用本次实际召回的知识版本和切片。
- 低优先级知识不得覆盖高优先级报文证据。
- 每个任务先补充失败测试，再实现行为，并运行相关测试和 Ruff。
- 数据库迁移必须可重复、可升级，不允许启动时猜测表结构。
- SQLite 写入事务保持短小，不能阻塞 Web API、Worker 或长时间诊断。
- 所有循环、候选数量、上下文字节、模型调用和检索时间必须有上限。
- 不提交知识数据库、本地 Embedding 模型、测试报文、分析产物、密钥、缓存和构建目录。
- Git 提交信息使用中文，每个任务形成范围明确的提交。

## 3. 阶段 R1：知识基础设施

### 任务 1：定义 RAG 领域契约与配置边界

状态：已完成（2026-07-27）

目标：固定知识、版本、切片、案例、查询、检索结果和引用的稳定数据结构。

工作内容：

- 定义知识类型、状态、权威等级和生命周期枚举。
- 定义文档、版本、切片、结构化案例和环境标签契约。
- 定义检索查询、候选结果、引用包和知识引用契约。
- 为字符串、列表、正文、标签和结果数量设置边界。
- 增加 `off`、`shadow` 和 `active` 运行模式及相关配置。
- 增加独立知识数据库路径、本地模型路径、Top K、超时和上下文预算配置。
- 定义 Embedding Provider、Knowledge Store 和 Retrieval Service 抽象。
- 配置序列化和日志不得暴露模型路径、导入绝对路径或凭据。

验收标准：

- 非法状态、额外字段、超长正文和伪造引用在服务边界被拒绝。
- 未安装 RAG 可选依赖时，基础 CLI 和 Web 仍能正常导入与运行。
- 默认模式不会让知识影响诊断结论。

建议提交：`feat: 定义RAG领域契约与配置`

### 任务 2：实现独立知识数据库与迁移

状态：已完成（2026-07-27）

目标：建立可版本化、可审核、可并发读取的本地 Knowledge Store。

工作内容：

- 建立独立 SQLite 数据库、WAL 模式和版本化迁移。
- 保存知识文档、版本、切片、结构化案例、Embedding 元数据和审计事件。
- 建立 FTS5 虚拟表及与正式切片的一致性维护机制。
- 建立状态、类型、版本、内容哈希、时间和父文档索引。
- 实现新增草稿、读取、分页列表、审核、停用、替代和版本查询。
- 使用事务保证知识状态、FTS 索引和索引代次一致。
- 启动时检测当前 Python SQLite 是否支持 FTS5，并提供稳定错误和恢复建议。

验收标准：

- 数据库初始化和迁移可重复执行，不破坏已有版本。
- API 与 Worker 分进程读取时不会持有长期写锁。
- 草稿、停用和过期版本不会出现在生产检索视图中。
- 数据库不保存原始报文、密钥和未经脱敏的本地路径。

建议提交：`feat: 增加RAG知识数据库`

### 任务 3：实现知识解析、脱敏与类型化切分

状态：已完成（2026-07-27）

目标：将 Markdown、文本和 JSON 案例转换成可审核的稳定切片。

工作内容：

- 实现文件类型、大小、编码和内容哈希校验。
- 支持 Markdown、纯文本和 JSON 结构化案例导入。
- 按标准文档、厂商资料、内部手册和历史案例分别切分。
- 保留标题层级、章节位置、适用条件、表格和命令上下文。
- 实现 IP、域名、账号、工单号、客户标识和路径的可配置脱敏。
- 标记疑似 Prompt 注入内容，要求审核人明确处理后才能发布。
- 生成草稿预览、解析警告和切片统计。
- 对同内容哈希、重复版本和结构缺失提供确定性错误。

验收标准：

- 相同输入产生稳定切片顺序和内容哈希。
- 表格、命令和阈值不会脱离其适用条件。
- 历史案例缺少确认主因、处置结果或审核信息时不能发布。
- 敏感信息不会进入切片、Embedding 输入或错误日志。

建议提交：`feat: 实现RAG知识导入与切分`

### 任务 4：实现本地 Embedding 与向量索引

状态：已完成（2026-07-27）

目标：为中英文混合知识建立可重建、可离线运行的语义索引。

工作内容：

- 增加独立 `rag` 可选依赖和跨平台安装说明。
- 实现本地 Embedding Provider，并支持配置模型缓存目录或离线模型路径。
- 按 E5 约定分别处理查询和知识正文前缀。
- 保存模型名称、维度、内容哈希和生成时间。
- 对向量维度、NaN、空向量和模型版本不一致进行校验。
- 实现批量生成、断点续建、重建和索引代次更新。
- 每个进程按索引代次加载有界只读向量矩阵并安全刷新缓存。
- 达到 25,000 正式切片上限时拒绝继续发布并给出迁移建议。

验收标准：

- 已下载或指定本地模型后，Windows 和 macOS 均可离线建立索引。
- 重建失败不会破坏上一个可用索引。
- Embedding 模型缺失只影响 RAG，不影响基础诊断和 Web 启动。
- Fake Provider 测试不依赖网络和大型模型下载。

建议提交：`feat: 增加本地知识向量索引`

### 任务 5：提供知识生命周期 CLI

状态：已完成（2026-07-27）

目标：通过 `pkm knowledge` 完成首版知识管理和审核。

工作内容：

- 提供导入、列表、查看、审核、停用、重建索引和健康检查命令。
- 所有有副作用操作先展示目标知识、版本、警告和结果摘要。
- 审核和停用记录操作者标识、时间和原因。
- 列表支持状态、类型、语言和更新时间过滤及分页。
- 导入和重建显示有界进度，不输出完整知识正文和绝对路径。
- 对空库、FTS5 缺失、模型缺失、数据库锁和非法状态提供中文恢复建议。
- 保持 `pkm web`、`pkm chat` 和 `pkm diagnose` 行为兼容。

验收标准：

- 用户可从文件导入草稿、审核发布、检索确认和停用版本。
- 重复命令保持幂等或明确拒绝，不产生重复正式版本。
- Windows PowerShell 和 macOS zsh 的空格、中文路径均可使用。

建议提交：`feat: 增加知识库管理命令`

## 4. 阶段 R2：混合检索与评估

### 任务 6：实现结构化知识查询构建器

状态：已完成（2026-07-27）

目标：从诊断上下文、候选原因和用户问题生成不泄露敏感信息的检索查询。

工作内容：

- 从方向、达标率、全局指标、SYN 选项、异常流和异常区间提取稳定特征。
- 从基础候选原因提取原因术语、反向证据和缺失证据。
- 从用户问题中保留允许的协议、设备、系统和场景术语。
- 生成关键词查询、向量查询文本、硬过滤条件和软匹配标签。
- 对数值特征进行区间化，避免把偶然精确值当作唯一匹配条件。
- 对路径、IP、密钥、Payload 和日志字段进行递归过滤。
- 查询为空或信息不足时明确跳过检索，不生成宽泛无界查询。

验收标准：

- 相同诊断上下文生成稳定查询。
- 查询不包含原始报文、绝对路径、密钥和完整逐包数据。
- 默认下载、显式上行和双向场景能生成正确方向过滤。

建议提交：`feat: 构建结构化RAG查询`

### 任务 7：实现混合检索、融合与重排

状态：已完成（2026-07-27）

目标：将关键词、向量和案例结构化相似度合并为有界高质量结果。

工作内容：

- 实现元数据硬过滤和环境适用性判定。
- 实现 FTS5/BM25 Top 20 召回。
- 实现归一化向量点积 Top 20 召回。
- 使用 RRF 合并候选并保持稳定的并列排序规则。
- 对历史案例计算方向、达标率、TCP 指标、SYN 选项和环境标签相似度。
- 根据适用条件、权威等级、时效性和案例相似度重排。
- 实现父文档去重、知识类型多样性和最低相关性阈值。
- 最终限制为 8 条和 24 KB，并生成完整引用包。

验收标准：

- 精确 TCP 术语和语义相似描述都能被召回。
- 不适用环境、停用版本和低相关结果不会进入最终上下文。
- 结果融合顺序在 Windows 与 macOS 上保持确定性。
- 25,000 切片容量测试的 P95 检索时间不超过 2 秒。

建议提交：`feat: 实现RAG混合检索与重排`

### 任务 8：实现知识引用验证器

状态：已完成（2026-07-27）

目标：阻止伪造、过期、不适用或无法支持陈述的知识引用进入结果。

工作内容：

- 校验引用是否属于本次召回包。
- 校验知识、版本、切片、审核状态和有效期。
- 校验适用条件与当前环境是否冲突。
- 区分知识支持陈述、当前报文支持陈述和报文外假设。
- 发现知识与报文证据冲突时保留冲突并降低知识结论等级。
- 无法验证的知识陈述标记为待外部验证或从最终输出移除。
- 为报告和问答提供统一知识引用快照结构。

验收标准：

- 不存在、跨版本、跨查询和停用引用均被拒绝。
- 历史案例相似性不会被误写成当前报文直接证据。
- 报告保存后仍能展示当时的来源和引用摘要。

建议提交：`feat: 增加知识引用确定性校验`

### 任务 9：建立 RAG 离线评估框架与基线

目标：用可重复指标判断 RAG 是否有资格影响诊断。

工作内容：

- 定义评估问题、相关知识、适用条件、期望原因和禁止结论格式。
- 支持 Recall@5、MRR、nDCG@5、引用准确率和适用条件准确率计算。
- 记录检索延迟、上下文字节和 Token 增量。
- 固化无 RAG 诊断基线和影子模式结果对比。
- 提供机器可读结果和中文摘要，不记录隐藏推理。
- 建立少量无网络测试夹具，验证评估器本身。
- 为正式评估集提供导入模板、脱敏检查和人工审核流程。

验收标准：

- 同一索引和评估集产生可重复指标。
- 缺失标注、重复 ID 和泄露敏感信息的样本被拒绝。
- 未达到上线门槛时配置层拒绝启用 `active`，或启动时明确降级为 `shadow`。

外部验收依赖：至少 50 条经过脱敏和人工标注的正式评估样本。代码实现可以完成，但没有这批样本时 RAG 只能保持 `shadow`。

建议提交：`test: 建立RAG离线评估基线`

## 5. 阶段 R3：诊断与问答接入

### 任务 10：接入 RAG 影子模式与运行轨迹

目标：在不改变当前诊断结果的前提下验证真实任务召回质量和运行稳定性。

工作内容：

- 在共享应用服务中注入 Retrieval Service，不让 CLI 或 Web 直接访问知识数据库。
- 完成基础候选原因后执行影子检索。
- 记录查询标签数量、候选数量、知识 ID、版本、排名、分数和耗时。
- 不记录完整知识正文、用户问题、绝对路径或模型消息。
- RAG 关闭、空库、超时、模型缺失、数据库锁和索引损坏均返回稳定降级状态。
- 在健康检查中只展示 RAG 模式、索引是否可用、文档数和版本，不返回敏感配置。

验收标准：

- `shadow` 模式与关闭 RAG 时生成的诊断主因和候选原因保持一致。
- 任何 RAG 故障均不导致基础诊断失败。
- CLI 和 Web 使用相同检索服务、配置和 trace 契约。

建议提交：`feat: 接入RAG影子检索模式`

### 任务 11：将 RAG 接入主诊断 LangGraph

目标：在通过评估后允许已验证知识补充候选原因、适用条件和建议。

工作内容：

- 增加知识检索和候选原因补充节点。
- 保持基础 `reason` 节点只依据当前报文，避免检索前锚定。
- 为知识增强模型调用定义严格输入输出和一次修复边界。
- 知识只能补充原因、适用条件、机制解释和排查建议。
- 复核节点同时验证报文证据和知识引用。
- 无命中、超时或验证失败时沿用原图路径。
- 报告明确标识报文证据、知识经验、冲突和待外部验证内容。
- 限制额外模型调用数、Token、检索轮次和总耗时。

验收标准：

- 高质量知识能够补充基础模型遗漏的合理原因。
- RAG 不会把无报文支持的案例原因直接设为已确认主因。
- 不合法引用和冲突知识不会进入最终报告。
- 关闭 RAG 后当前所有诊断回归保持兼容。

建议提交：`feat: 将RAG接入诊断图`

### 任务 12：将 RAG 接入分析后持续问答

目标：让用户在追问协议机制、相似案例和处置方法时获得可引用知识。

工作内容：

- 在问答准备阶段确定当前问题是否需要知识检索、报文取证或两者。
- 基于当前报告、诊断上下文和问题构建有界知识查询。
- 问答模型同时接收有界报文证据和知识引用包，并明确二者类型。
- 问题涉及具体帧、流、时间或指标时继续优先调用 MCP。
- 验证回答中的报文引用和知识引用，拒绝跨 analysis_id 或跨检索包引用。
- 对无相关知识、知识冲突和报文外问题给出明确限制。
- 保持现有问答取证轮次和请求数量上限。

验收标准：

- “为什么窗口会限制吞吐”可引用协议知识回答。
- “当前哪条流发生 Zero Window”只依据当前报文证据回答。
- “是否有相似案例”明确展示案例适用条件和差异。
- RAG 不可用时现有持续问答仍可使用。

建议提交：`feat: 增强RAG诊断追问`

### 任务 13：在 CLI 与 Web 展示知识引用

目标：让用户看清结论来自当前报文还是外部知识。

工作内容：

- 扩展报告和问答响应，增加兼容的知识引用字段。
- CLI 报告和问答展示标题、类型、版本、章节和支持陈述。
- Web 报告和消息增加知识引用区域，不与报文证据混排。
- 引用内容采用有界摘要，按需查询详情，不一次返回完整文档。
- 历史报告使用保存的引用快照，即使知识后续停用仍可追溯。
- 前端不获得知识数据库路径、原始导入路径和审核凭据。
- 对无 RAG 旧报告保持兼容渲染。

验收标准：

- 用户能明确区分报文直接证据、知识经验和外部假设。
- 旧报告和关闭 RAG 的结果不会因新增字段无法显示。
- CLI 与 Web 对同一报告展示相同引用语义。

建议提交：`feat: 展示RAG知识引用`

## 6. 阶段 R4：发布门禁与文档

### 任务 14：强化安全、故障恢复与跨平台验证

目标：确认 RAG 不扩大敏感数据边界，也不降低 PacketMaster 可用性。

工作内容：

- 增加知识导入 Prompt 注入、路径、密钥和客户信息泄露测试。
- 增加数据库损坏、锁超时、索引代次变化和中途重建失败测试。
- 增加模型缺失、离线环境、向量维度变化和依赖未安装测试。
- 验证 API 与 Worker 多进程并发读取和缓存刷新。
- 验证 Windows 长路径、中文路径、文件锁、Conda 环境和离线模型目录。
- 验证 macOS 开发安装、索引、检索和 RAG 降级。
- 运行完整 Python、CLI、Web、打包和浏览器回归。
- 运行 25,000 切片容量与 P95 延迟门禁。

验收标准：

- 安全测试证明禁止内容不进入数据库、Embedding、模型、日志和浏览器。
- RAG 故障不会阻止 Web 启动、任务执行、报告读取和无 RAG 问答。
- Windows 真机和 macOS 自动化结果均记录在发布清单。

建议提交：`test: 完善RAG安全与发布门禁`

### 任务 15：完善使用、运维和评估文档

目标：提供从安装到启用 `active` 的完整操作说明。

工作内容：

- 记录基础安装与 RAG 可选依赖安装方式。
- 记录联网下载和 Windows 离线模型目录配置。
- 记录知识导入、审核、停用、重建、备份和恢复流程。
- 提供结构化历史案例模板和正式评估集模板。
- 说明 `off`、`shadow`、`active` 的区别和切换条件。
- 说明知识数据库、模型缓存和诊断产物的独立生命周期。
- 更新当前能力、CLI、Web、Windows 发布清单和故障排查文档。
- 明确 Qdrant Server 迁移触发条件，但不在 V1 实施迁移。

验收标准：

- 新环境可以只按文档完成安装、初始化、导入、审核、评估和影子运行。
- 未完成正式评估时，文档不会引导用户直接启用 `active`。
- 文档命令同时覆盖 `pkm` 短命令和 `packetmaster` 兼容说明。

建议提交：`docs: 完善RAG使用与发布说明`

## 7. 完整验收顺序

1. 运行领域契约、数据库、导入、切分、Embedding 和 CLI 单元测试。
2. 运行混合检索、引用校验和离线评估测试。
3. 运行诊断图、问答图、CLI、Web API 和前端引用展示集成测试。
4. 运行隐私、Prompt 注入、故障注入和多进程并发测试。
5. 运行全部非性能测试、Ruff、前端检查和构建。
6. 使用 25,000 个合成切片执行检索容量与延迟门禁。
7. 在 macOS 执行本地模型、真实知识导入、影子诊断和降级验证。
8. 在 Windows Conda 环境执行安装、离线模型、中文路径、Web Worker 和文件锁验证。
9. 导入不少于 50 条人工标注评估样本并生成基线对比报告。
10. 只有第 9 步达到 spec 门槛后，才允许将部署配置从 `shadow` 改为 `active`。

## 8. 完成定义

RAG V1 的代码完成需同时满足：

- 任务 1 至任务 15 的实现和自动化验收完成；
- 现有无 RAG CLI、Web、诊断和问答无行为回归；
- RAG 可选依赖未安装时基础 PacketMaster 正常运行；
- macOS 自动化和 Windows 真机发布门禁通过；
- 文档、配置示例、案例模板和评估模板齐全；
- 工作区不包含知识数据库、本地模型、密钥、报文和生成产物。

RAG V1 的生产启用还需额外满足：

- 首批正式知识经过人工审核；
- 不少于 50 条正式评估样本经过脱敏和标注；
- 评估达到 spec 第 15.3 节全部门槛；
- 评估报告和启用决定有可追溯记录。
