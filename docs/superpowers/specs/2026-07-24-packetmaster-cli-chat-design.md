# PacketMaster CLI 对话交互设计

日期：2026-07-24

## 1. 背景

PacketMaster 当前提供一次性 `packetmaster diagnose` 命令，能够对完整 TCP 测速报文执行本地分析、证据驱动诊断并生成结构化报告。用户获得报告后，仍需要理解候选原因、核对关键证据、追问原因之间的差异，并确定下一步排查动作。

本阶段增加持续运行的 CLI 对话模式。用户可以用一句自然语言描述诊断任务，系统自动抽取报文、标准带宽、实际带宽和方向；信息不完整或有歧义时再进行针对性追问。诊断完成后，用户围绕当前报告和本地证据继续问答。该能力不是通用聊天机器人，而是绑定当前分析任务、受证据约束的诊断会话。

## 2. 目标

新增 `packetmaster chat` 命令，完成以下闭环：

1. 从自由自然语言中抽取报文路径、标准带宽、实际带宽和分析方向，并补问缺失或歧义参数。
2. 复用现有 LangGraph 诊断流程完成第一次分析。
3. 将完整 `report.json` 通过确定性模板整理为中文自然语言，并作为同一终端会话中的首条诊断消息。
4. 接收用户对当前报告的自然语言追问。
5. 使用当前报告、全量聚合摘要和必要的分页证据回答问题。
6. 对需要额外报文证据的问题，通过 FastMCP 定向查询本地证据。
7. 支持开始新任务、重看报告、查看证据、查看帮助和退出。
8. 保持 Windows 正式运行兼容和 macOS 开发兼容。

## 3. 非目标

本阶段不包含：

- Web 对话页面。
- 语音输入输出。
- 多用户并发会话服务。
- 跨进程恢复完整聊天历史。
- 对多个报文任务进行横向对比。
- 允许模型执行网络配置、系统命令或外部变更。
- RAG 知识库和向量数据库。
- 将原始报文、Payload、完整日志或 API Key 发送给模型。

## 4. 用户流程

### 4.1 启动会话

用户执行：

    packetmaster chat

CLI 首先提示用户用自然语言描述诊断任务，例如：

    请分析 "D:\captures\测速 报文.pcapng"，标准带宽 1Gbps，实际 620M，分析下载。

自然语言参数抽取必须识别：

- 报文路径，支持带引号或不带引号、相对路径、Windows 和 macOS 路径。
- 标准带宽及单位，支持 Mbps、Gbps、M、G、兆、千兆等常见表达。
- 实际带宽及单位。
- 分析方向，支持下载、下行、上行、上传、双向、上下行等表达。

真实路径先由本地路径提取器识别并替换为不透明占位符，模型不得接收本地绝对路径。模型只抽取路径占位符、带宽数值、单位、方向和缺失项；确定性代码负责单位换算、路径恢复、文件校验和最终归一化。

用户未说明方向时固定使用 `download`。只有明确表达上行时使用 `upload`，明确表达双向或上下行时使用 `both`。模型不得因为报文中存在双向流自动推断 `both`。

如果一句话缺少路径或带宽，CLI 只追问缺失项。存在多个路径、带宽角色不明确、单位不明确或表达冲突时，CLI 必须追问，不得猜测。用户可以用自然语言修正已抽取参数，例如“实际带宽改成 580M”。

参数完整后，CLI 在本地展示规范化结果并请求确认。只有用户确认后才启动可能耗时较长的报文分析。用户拒绝时可继续自然语言修改；参数收集阶段始终支持 `/quit`。

### 4.2 执行诊断

参数完整后，CLI 调用现有诊断工作流并显示中文进度。诊断完成后，`report.json` 仍作为完整结构化结果原子写入磁盘；CLI 聊天框不直接打印 JSON，而是通过确定性报告叙述器整理为自然语言，依次说明：

- 本次分析的方向、标准带宽、实际带宽、达标率和覆盖完整性。
- 最可能原因、百分数置信度以及为什么将其排在第一位。
- 按置信度排序的全部合理候选原因，每条包含支持证据、反向证据、缺失证据和建议。
- 关键证据页及可追溯的帧号、相对时间、流 ID 等安全引用。
- 当前诊断限制、排查步骤和优化建议。
- JSON 报告的本地保存位置。

候选原因数量不设固定上下限。报告必须尽可能覆盖实际证据支持的合理原因，合并同义项，不为凑数量编造原因。

自然语言整理不得额外调用模型。报告叙述器只能使用 `DiagnosticReport` 已有字段，通过稳定中文模板组织为连贯段落和必要的编号列表，不得新增原因、证据或置信度。空字段应自然省略，不输出 `null`、空数组或内部字段名；`analysis_id`、哈希和内部错误元数据仅在排障确有必要时显示。

示例输出形态：

    PacketMaster> 分析已完成。本次分析的是下载方向，标准带宽为 1000 Mbps，实际带宽为 600 Mbps，达标率为 60%。报文覆盖完整，共分析 5016 个测速包。

    最可能的原因是“发送端应用层限速”，置信度为 70%。该原因排在第一位，是因为两个 TCP 流的吞吐均稳定在约 10 Mbps，且 RTT 很低、重传很少，暂未看到足以解释当前差距的网络拥塞证据。

    其他可能原因包括：……

    当前限制：……
    建议下一步：……

### 4.3 持续问答

诊断完成后进入 `PacketMaster>` 提示符。用户可以提出例如：

- 为什么把这个原因排在第一位？
- 零窗口发生在哪些流和时间点？
- 重传是否足以解释当前带宽差距？
- 第一个原因应该如何进一步排查？
- 哪些结论无法仅凭报文确认？

每个回答必须绑定当前 `analysis_id`，并区分：

- 已由报文或全量聚合直接支持的事实。
- 由指标间接支持的判断。
- 报文外、尚需用户核查的信息。

回答不能声称已经观察到上下文和证据中不存在的事实。

### 4.4 内置命令

第一版支持：

- `/new`：结束当前问答上下文，开始收集新的诊断参数。
- `/report`：使用同一确定性模板重新输出当前完整自然语言诊断报告和 JSON 路径。
- `/evidence`：显示当前报告的关键证据页及可追溯引用。
- `/save`：显示当前 JSON 报告路径；报告已在诊断完成时落盘。
- `/help`：显示命令列表。
- `/quit`：正常结束会话。

命令采用确定性解析，不交给模型识别。未知 `/` 命令应提示帮助，不作为自然语言问题发送给模型。

## 5. 会话状态

新增独立于诊断 `AgentState` 的 `ChatSessionState`，至少包含：

- `session_id`：当前 CLI 会话标识。
- `pending_intent`：当前自然语言抽取出的参数、缺失项、歧义项和确认状态。
- `analysis_id`：当前报文分析任务标识。
- `target`：download、upload 或 both。
- `standard_bandwidth_mbps` 和 `actual_bandwidth_mbps`。
- `report`：当前结构化诊断报告。
- `report_path`：本地报告路径，仅供 CLI 使用，不发送给模型。
- `diagnosis_context`：全量聚合形成的有界上下文。
- `conversation_turns`：经过清理和裁剪的最近问答。
- `conversation_summary`：较早问答的有界摘要。
- `question`：当前用户问题。
- `requested_evidence`：当前问题需要的证据请求。
- `collected_evidence`：当前问题已获取的分页证据。
- `answer`：结构化问答结果。
- `inspection_count`：当前问题的额外取证次数。
- `error`：结构化错误。

状态不保存原始报文内容、完整逐包数据、完整模型响应、隐藏推理或 API Key。

## 6. 问答输出契约

新增 `ChatAnswer` 结构化模型，至少包含：

- `answer`：简体中文直接回答。
- `evidence_basis`：支撑回答的聚合事实或证据引用。
- `limitations`：当前回答无法确认的部分。
- `follow_up_suggestions`：用户可执行的下一步核查建议。
- `requested_evidence`：回答前仍需获取的安全证据请求。
- `ready`：是否可以形成最终回答。

所有用户可见文本使用简体中文。TCP、RTT、ACK、Mbps 等技术缩写可以保留。Schema 枚举、证据字段、流 ID、IP 地址和协议标识不得翻译。

回答必须简洁、针对当前问题，不重复输出整份诊断报告。需要展示报文证据时，只引用帧号、相对时间、流 ID、方向、事件类型和允许的 TCP 字段。

## 7. 问答工作流

问答使用单独的有界 LangGraph，不修改已经稳定的诊断图节点。建议节点如下：

1. `prepare_question`：校验当前会话和问题，构建有界问答上下文。
2. `answer_question`：模型基于报告、摘要和已有证据生成回答或证据请求。
3. `inspect_question_evidence`：通过 FastMCP 获取分页证据。
4. `verify_answer`：模型使用新增证据修正答案和限制。
5. `finalize_answer`：写入会话历史并输出中文回答。

`answer_question → inspect_question_evidence → verify_answer` 构成问答取证循环。每个用户问题最多执行两轮额外取证，每轮最多 5 个证据请求。达到上限后必须带限制输出，不得无限调用工具。

问答模型可以请求现有 `get_tcp_evidence` 支持的证据类型，不能产生任意 SQL、Shell、TShark 参数或未列入 Schema 的字段。

## 7.1 自然语言参数抽取流程

参数抽取位于诊断图之前，不与报文证据问答混用：

1. `extract_local_paths`：在本地识别 pcap/pcapng 路径，生成占位符映射。
2. `parse_diagnosis_intent`：模型从清理后的自然语言中输出严格结构化意图。
3. `normalize_parameters`：确定性换算带宽单位、归一化方向并恢复路径。
4. `validate_parameters`：检查文件、正数带宽、冲突和缺失项。
5. `clarify_or_confirm`：只追问缺失或歧义字段；完整时展示确认摘要。

模型抽取结果必须包含每个字段的状态：`resolved`、`missing` 或 `ambiguous`。模型不能访问文件系统、调用 MCP、开始诊断或自行确认。连续修正采用字段级合并，新值只覆盖用户明确修正的字段。

当模型不可用、抽取超时或结构化校验失败时，CLI 降级为逐项引导输入，用户仍能完成诊断。

## 8. 上下文与记忆边界

模型每次回答只接收：

- 当前问题。
- 当前诊断报告。
- 与问题有关的紧凑 `DiagnosisContext`。
- 最近若干轮经过清理的问答。
- 较早对话的有界摘要。
- 当前问题按需查询的分页证据。

默认保留最近 8 个问答轮次。超过限制的旧轮次压缩为摘要；摘要和最近轮次的合计序列化大小必须有硬上限。任何层级都继续使用现有敏感字段清理规则，排除 Payload、Authorization、Token、API Key、完整日志和本地绝对路径。

对话历史只用于理解代词和追问关系，不能作为报文事实来源。用户在对话中提出的猜测必须标记为用户假设，除非本地证据能够验证。

## 9. 复用本地产物

首次诊断继续对完整报文执行全量流式分析。后续问答不得重新扫描完整报文，除非用户通过 `/new` 发起新任务。

Real Adapter 根据 `analysis_id` 从 `artifacts/<analysis_id>/` 恢复 `analysis.sqlite`、聚合 JSON 和筛选报文，支持 MCP 证据查询。CLI 会话期间任务目录使用 active 标记防止过期清理；会话正常或异常退出时移除 active 标记。是否长期保留仍遵循现有 TTL 和 keep 规则。

## 10. CLI 行为

### 10.1 输入体验

- 路径支持相对路径、Windows 盘符、反斜杠、空格和中文。
- 带宽只接受有限正数。
- `Ctrl+C` 在参数输入或问答提示符处取消当前会话并正常清理；分析子进程运行时沿用现有跨平台终止逻辑。
- EOF 视为正常退出。
- 空问题不调用模型，直接重新显示提示符。
- 不使用 `shell=True`，不执行用户输入内容。

### 10.2 输出体验

- 进度、错误、回答和命令帮助使用简体中文。
- 问答提示符稳定，不因长文本或异步进度发生错位。
- 自然语言报告较长时保持段落和编号结构，不把整份 JSON 压成单行，也不使用终端宽度相关的脆弱表格。
- 模型或证据查询失败时输出结构化、可操作的错误，不终止整个会话；用户仍可使用 `/report`、`/new` 或 `/quit`。
- 不在终端打印完整模型请求、API Key、Payload 或完整日志。

## 11. 组件变更

建议新增或调整：

- `domain.py`：增加问答请求、回答和会话领域模型。
- `chat.py`：管理会话状态、命令解析和参数收集。
- `chat_graph.py`：构建有界问答 LangGraph。
- `model.py`：增加结构化问答和答案复核能力，复用 DeepSeek `json_mode` 兼容策略。
- `prompts/chat_answer.md` 和 `prompts/chat_verify.md`：问答与复核 Prompt。
- `cli.py`：增加 `chat` 命令和交互循环。
- `report.py`：增加完整结构化报告到中文自然语言叙述的确定性渲染能力，以及证据和回答的终端渲染辅助能力。
- `artifacts.py`：保证会话期间 active 生命周期正确。

现有 `diagnose` 命令和 JSON 报告契约必须继续兼容。

## 12. 安全要求

- 原始 pcap/pcapng 不进入模型。
- `tcp.payload`、完整日志、API Key、Token 和 Authorization 不进入模型或聊天历史。
- 本地绝对路径不进入问答模型上下文。
- 模型证据请求必须经过 Pydantic Schema 和 Adapter 白名单双重校验。
- 用户问题视为不可信输入，不能改变系统安全规则、工具白名单或分析方向。
- 诊断意图文本视为不可信输入；其中的命令、Prompt 注入或工具调用要求只能作为普通文本处理。
- 回答只提供诊断和排查建议，不自动执行系统或网络变更。
- trace 只记录节点、轮次、状态、错误码和请求数量，不记录完整问题或回答正文。

## 13. 错误与恢复

- 首次诊断失败：保留结构化错误，允许 `/new` 或 `/quit`，不进入无依据问答。
- 模型问答超时：提示可重试，当前报告仍可查看。
- 结构化回答失败：沿用一次 Schema 修复重试，仍失败则返回 `INVALID_MODEL_OUTPUT`。
- 证据不存在：模型必须基于已有报告回答并明确限制。
- 产物已过期：提示重新执行 `/new`，不得静默重新分析旧路径。
- 用户中断：清理 active 状态和运行中的子进程，不损坏已有报告。

## 14. 测试与验收

必须覆盖：

- 一句话完整抽取路径、标准带宽、实际带宽和方向。
- 缺失参数的针对性追问、歧义参数澄清和自然语言字段修正。
- 未说明方向时默认 download，显式 upload 和 both 正确归一化。
- Mbps、Gbps、M、G、兆和千兆等单位换算。
- 路径本地提取、占位符替换和模型输入路径脱敏。
- 参数确认前不启动分析，拒绝确认后允许继续修改。
- 模型抽取失败时降级为逐项引导输入。
- 诊断完成后自动输出由完整 `report.json` 整理的自然语言报告。
- 自然语言报告覆盖概览、主因、全部候选、证据、限制、排查步骤、优化建议和 JSON 路径。
- 报告自然语言渲染不调用模型、不新增事实，并能正确省略空字段。
- `/report` 重复渲染结果与首次诊断消息一致。
- 相对路径、Windows 路径、空格和中文路径。
- 无效路径、带宽和方向的本地重试。
- `/new`、`/report`、`/evidence`、`/save`、`/help`、`/quit`。
- 问答不重新执行基础报文分析。
- 问题需要证据时调用 FastMCP，最多两轮、每轮最多 5 个请求。
- 无证据时明确限制，不编造帧号和事件。
- 对话历史裁剪和敏感字段递归清理。
- DeepSeek `json_mode` 的结构化问答和一次修复重试。
- 模型、MCP、产物过期和 Ctrl+C 的恢复路径。
- 现有 `packetmaster diagnose` 回归不受影响。

验收场景：使用确定性虚拟报文启动 `packetmaster chat`，输入一句包含报文路径、标准千兆、实际 600M 的自然语言且不说明方向；系统抽取为 download，在不向模型暴露真实路径的前提下展示确认信息。用户确认后完成诊断，CLI 自动把完整 `report.json` 整理成中文自然语言报告，再连续询问主因依据、零窗口位置和排查建议；报告和回答均为中文，证据引用可在本地索引中定位，原始 Payload 和密钥不出现在模型输入、终端或 trace 中；`/report` 可复现相同报告，随后 `/new` 可开始另一任务，`/quit` 正常退出。

## 15. 后续扩展

完成本阶段后可以继续增加：

- `/resume <analysis_id>` 恢复历史报告和问答。
- RAG 接入 TCP 标准、设备知识和历史案例。
- 多报文任务对比。
- Web 或桌面对话界面。
